# Review A: the solver's turns switch (2026-11-13)

**Verdict: sound with changes.** The finding holds; the fix is correct and complete for every path that makes the own body. Before it is relied on: check whether the own body ever sleeps (finding 3), show switch-off is bit-identical in the game body (7), and make the bench say its turns (9).

## Findings

1. **The switch's first run says what the report says it does.** Evidence: `D:/Dev/WG/TestRuns/turnsswitch_r.xml`, both tests Passed (`ArticulationFactsTests.TheSolversTurnsSetBeforeTheLinksAreKept`, `OwnBodyTests.EachMinersOwnBodyRunsAtItsOwnTurns`); `turnsswitch.log` lines 1141/1167/1193 (`FACTS turns kept`, the fifth way "made with no turns set (read back as made: 6 and 1, sleeping below 0.005) ... the same course as as made to the last bit" for Small, Long, Round; the after-links way reads "14 and 4, sleeping below 0") and line 1273 (`OWN_TURNS`: 14/4 as made, 6/1 off, 14/4 on, root 7.880/9.677/23.629 kg, damped 0 and 0, at most 20, at most 1.5, Continuous; Small getting up 15 parts, 14 and 4). Weight: note. Do: nothing; the claims hold as read.

2. **The finding holds, by two independent readings.** Evidence: the facts rig reads back 6 and 1 when 14 and 4 were set before the links, 14 and 4 when set after (log lines 1141/1167/1193), and the courses agree with the read-back: as made = set again to 6/1 = made with no turns, all to the last bit; set again to 14/4 = made with turns after links, to the last bit, and differs from as made (29.65/53.27/13.72 mm). The sleep threshold, set by the rig beside the turns (`ArticulationFactsTests.cs` 1366/1385: `weight.sleepThreshold = 0` in the same branch), is lost the same way (0.005 before, 0 after), so the loss is of the whole-articulation settings, not a quirk of the turns' getter. Another explanation (e.g. a read-back of a cached value while the solver uses the set one) is ruled out by the courses. Weight: note. Do: nothing.

3. **The game's own body never sets a sleep threshold, so it sleeps below the default 0.005 whatever the switch.** Evidence: no `sleepThreshold` anywhere in `Scripts/` (grep); the facts rigs all set 0 deliberately (`ArticulationFactsTests.cs` 589, 1221, 1366/1385; `OwnBodyTests.cs` 1083). The whole-articulation settings in PhysX are the solver counts, the sleep and stabilization thresholds, the wake counter and the fixed base (`immovable`); of these OwnBody sets only `immovable = false` (the default, so its loss would change nothing) and, now, the turns after the links. A miner standing quietly at rest, its breath small (by the project's own rule), could fall under the threshold and be put to sleep, freezing its life at rest until something wakes it. Weight: should. Do: a short read, not a fix: over a long still stand at low strength, log `root.IsSleeping()` each step for all three miners; if it ever sleeps, decide (with the Director, as it changes feel) whether to set the threshold, after the links, beside the turns in `KeepTurns`.

4. **The root link's own settings read back as set, but only by their getters.** Evidence: `OWN_TURNS` (log line 1273): mass, damping 0/0, maxAngularVelocity 20, maxDepenetrationVelocity 1.5, Continuous. These are per-link (rigid-body) properties in PhysX, not articulation-level, so there is no reason to expect them lost; and the turns showed the getters do reach the engine's state. Still, the turns' finding was made certain by courses, not by getters. Weight: note. Do: if wanted, one facts-style way in `TheSolversTurnsSetBeforeTheLinksAreKept` with the root's mass and damping set after the links, run against "as made" to the last bit; identical courses close it.

5. **The bench's post rig (`BodysOwnBench.cs` 594) sets `root.immovable = true` before the link is added**, the one whole-articulation setting there that is not the default. If it were lost like the turns the post would fall; nothing reads it back. Weight: note. Do: read `root.immovable` back once in that rig (or confirm the post stays put in its log).

6. **The fix is correct and complete for every path that makes the own body.** Evidence: `Begin`, `BeginLow`, `BeginDown` and `Remake` all go through `Make` (`OwnBody.cs` 581/589/598/651); `Make` calls `KeepTurns()` at 857, after the build loop and the toes (839), before `Stands = true` (900); `Advance` calls it each step after `if (!Stands) return` (1071-1074), and `FixedUpdate` calls `Advance` before the physics step, so a switch turned while it stands takes hold on the next step (the test reads it after two). A bench in Script mode that calls `own.Advance` gets the same. Small getting up reads 14/4 with 15 parts joined. Off, `TurnsNow` is `Physics.defaultSolverIterations`, set after the links, which the facts' second way ("set again to 6 and 1") shows is the same course to the last bit as the leg as made. `RestoreRest` (`OwnBodyTests.cs` 50) restores the switch after each test, `TestArguments` at suite end. Weight: note. Do: nothing.

7. **"Switch off is the game as played" is shown on the facts rig, not on the game's own body.** Evidence: the fifth way is a three-link leg (`StandingLeg(..., turnsNot: true)`); `EachMinersOwnBodyRunsAtItsOwnTurns` checks only read-back turns. Do: one deterministic own-body course (e.g. a stand, a nudge, and Small's get-up on the bench) at `2ed1c7c` and with the diff, switch off, compared to the last bit, in the worktree.
